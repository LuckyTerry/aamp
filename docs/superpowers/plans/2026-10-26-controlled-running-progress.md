# 受控任务恢复执行中默认进度

用户要求先修复已确定的问题，并将移动端问题交由移动端同学处理。本次仅修改飞书 bridge，恢复旧流程的“正在执行”文案；不修改移动端、Task 服务端、PB、IDL 或数据库。

## 行为

受控任务收到真实运行信号并成功上报 RUNNING 后，通过现有 Task Patch 接口单独写入 `agent_task_progress`，携带当前 `execution_id`。状态仍由新反馈接口维护，不再重复调用旧状态写入。进度成功后同一轮重复流事件不重复写；失败不把执行置为失败，后续运行事件可以重试。停止、终态及已被新执行替换的旧轮不发起进度写入，异步返回不能恢复旧任务快照。

沿用现有上报记录与执行保护，不引入新的持久字段、协议或后台重试。旧流程仍使用原有状态和进度写入。

停止命令发送期间不再发起默认进度请求。已发出的同轮进度请求可能在网络中晚于暂停反馈完成，但只写进度文本；不为此改动原有 STOP 或 BLOCKED 反馈行为。
