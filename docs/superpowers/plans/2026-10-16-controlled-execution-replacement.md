# 同任务的新执行替换旧执行

用户已确认：新一轮到达后，AAMP 取消同任务未结束的旧轮，旧轮不再回写 Task，清理后启动新轮。只修改现有受控 Task 链路，普通任务和其他 Task 的执行保持原逻辑；不改 Task PB、IDL 或数据库。2026-10-16 用户追加授权：服务端部署 BOE，AAMP 完成后更新本地包并启动。

## 实现

1. 飞书 bridge 在同任务串行队列中核对 START，复用事件已有的毫秒 `create_time`，拒绝比当前轮更早、相同时间或缺失时间的不同轮；不按 UUID 大小排序。已有存量本地记录无原事件时间时，允许首次新命令接管。
2. 持久保存旧轮的 `supersededByExecutionId`，清理旧输出缓冲。旧 ACK、状态、评论、步骤、产物与结果不再写 Task。新 dispatch 在已有字符串上下文中携带 `execution_id`、`task_execution_policy=replace_previous` 与事件原时间；不改 SDK 协议。
3. ACP bridge 只接受同 dispatcher、同 stable sessionKey、显式 replace 策略的新 execution。旧轮先正常取消，超过 2 秒只终止旧 prompt 对应进程，同时结束旧 cancel 命令。确认本地退出后释放锁，开始新轮；不得停止整个 AcpxClient。无法清理时新轮失败，不能强行并行。
4. 若强制终止后会话不可复用，新执行使用独立 ACP session；同一 execution 的后续评论续跑继续该 session。相同 execution 的重复命令不触发替换。
5. 飞书回调和 START/STOP 使用不同队列。旧轮的回调网络等待可以失效，已发出的 HTTP 请求不阻塞新 START；返回后仍须检查本地旧轮标记，不能恢复旧状态或继续写入。上下文读取和进度上报的悬挂等待也不能阻止 ACP 旧轮本地清理。
6. 已经活跃的执行时间不因历史缓存被其他 Task 挤出而丢失。强制终止后的会话别名按任务保留，保证后续评论续跑继续正确会话。新命令必须显式允许替换；升级前缺少该标记的旧受控轮仍可被识别并取消。

## 验证与限制

按用户要求只编写回归用例，暂不执行单测；执行 TypeScript 编译、静态复核、构建。覆盖旧输出隔离、重复 START、迟到旧 START/STOP、不同 Task 不互相终止、取消超时、定向终止失败以及同轮评论续跑。

本地终止不撤销已经发生的文件修改或外部操作，也不能保证脱离进程组或远端自行运行的工具已停止。本轮不扩展跨机器执行控制。部署成功与真实任务复测分开记录到既有联调表。
